# AI电商主图/详情页生成管理系统 \- 知识库增强产品架构方案

## 一、方案总览

### 1\. 建设目标

在**不改动系统原有业务功能**（账号登录、项目管理、生图任务队列、图片预览 / 下载、API 配置、产品图匹配等）的基础上，升级现有知识库模块，搭建**部门权限管控体系**，实现账号绑定部门、部门配置专属业务场景、文档上传解析、智能检索、提示词动态增强能力。支持各部门AI绘图、对话场景独立调用专属提示词模板、产品资料、设计规范，做到部门资源隔离、权限分级管控、新旧模式可一键切换，兼容 Markdown/TXT/PDF 等常用文档格式。

### 2\. 适用范围

- 业务场景：电商主图生成、详情页分镜生成、海报设计、AI 对话问答

- 文档类型：AI 绘图提示词（Markdown 为主）、产品说明文档、设计规范、运营文案

- 使用角色：管理员（全权限）、运营人员（使用知识库、生图）

### 3\. 核心设计原则

1. **无侵入改造**：所有新增模块为增量设计，原有功能、数据、流程完全保留，上线零风险。

2. **开关可控**：提供全局启用 / 关闭开关，关闭则完全回归原有系统逻辑。

3. **部门隔离**：按用户所属部门划分知识库归属，不同部门资源隔离，同部门共享可用业务场景与模板，杜绝跨部门数据干扰。

4. **容错降级**：知识库异常、检索失败、文档超长时自动降级，不阻断核心生图流程。

5. **复用现有技术栈**：基于现有 Next\.js \+ TypeScript \+ Ant Design \+ Prisma \+ SQLite 架构扩展，不新增底层框架。

### 4\. 整体业务流转（新增部门权限联动）

```Plain Text
文档上传 → 自动解析+文本清洗+关键词提取 → 绑定所属部门、配置部门业务场景 → 数据入库（知识库）
用户登录鉴权 → 读取账号所属部门 & 部门授权业务场景
用户发起生图/对话请求 → 开启知识库开关 → 系统按「用户部门+部门授权场景+用户输入」智能检索本部门知识库
拼接标准模板+用户需求生成增强提示词 → 调用iThinkAPI执行生成/对话 → 沿用原有任务队列、图片存储、结果输出流程
```

## 二、整体产品架构

### 1\. 架构分层

采用**前端展示层、应用服务层、数据持久层**三层架构，新增能力全部内嵌至原有分层中，不拆分独立服务。

|架构分层|原有能力|新增知识库能力|
|---|---|---|
|前端展示层|登录页、项目管理、生图工作台、知识库基础管理、API 配置、用户管理|1\. 知识库编辑页扩展（绑定部门、配置部门业务场景、关键词配置）<br>2\. 生图工作台新增「知识库启用开关」，自动适配当前账号部门权限<br>3\. 对话界面复用知识库权限逻辑，严格按部门权限过滤资源|
|应用服务层|文件上传解析、产品图匹配、生图任务调度、iThinkAPI 调用、权限校验|1\. 通用文档解析服务（MD/TXT/PDF）<br>2\. Markdown 格式自动清洗服务<br>3\. 关键词自动提取服务<br>4\. 通用知识库检索服务<br>5\. 提示词动态拼接服务|
|数据持久层|SQLite 数据库、Prisma 数据模型、本地文件存储|1\. 知识库数据表字段扩展<br>2\. 上传文件本地存储（沿用原有目录）<br>3\. 生成图片存储（无改动）|

### 2\. 系统模块划分

整体分为**原有核心模块**和**新增知识库增强模块**两大板块，模块间低耦合、独立运行。

#### 2\.1 原有核心模块（完全保留，无修改）

1. **账号权限模块**：账号密码登录、会话 Cookie、管理员 / 运营角色区分、用户管理

2. **项目管理模块**：项目创建、项目列表、生图工作台基础能力

3. **产品匹配模块**：产品白底图同名 / 别名 / 模糊 / 手动匹配

4. **生图任务模块**：任务队列、调用 iThinkAPI、图片本地存储、预览 / 单张下载 / 项目 ZIP 打包下载

5. **API 配置模块**：iThinkAPI 密钥配置、接口测试

#### 2\.2 新增知识库增强模块（增量扩展）

##### （1）文档上传与解析子模块

- 能力：接收前端上传文件，支持 `.md`/`.txt`/`.pdf` 格式

- 核心功能：文件本地存储、文档正文提取、Markdown 语法标签清洗、空行 / 特殊符号过滤、自动提取文档关键词

- 存储路径：沿用原有 `storage/uploads` 目录，不改动目录结构

##### （2）知识库数据管理子模块

基于原有知识库数据表扩展字段，提供后台管理能力：

1. 基础管理：文档启用 / 禁用、优先级设置、别名管理（原有功能保留）

2. 新增配置项：**自定义关键词**、**业务场景标签**、文档正文预览

3. 权限控制：管理员可编辑 / 删除所有知识库，运营仅可查看使用

##### （3）智能检索子模块（通用核心服务）

全局统一检索能力，供生图、对话全场景复用，检索规则分层设计：

1. 前置过滤：仅检索「已启用」的知识库，优先返回标记为「优先匹配」的内容

2. 匹配优先级：部门精准匹配 → 部门授权场景匹配 → 文档名称匹配 → 别名匹配 → 关键词匹配 → 正文模糊匹配

3. 限制规则：控制返回知识库数量、单文档字符长度，避免提示词超长

##### （4）提示词增强子模块（部门权限可控）

区分**绘图场景**和**对话场景**两套拼接逻辑，基于**用户部门\+部门授权场景**过滤可用知识库，适配不同部门业务需求：

1. 绘图场景（主图 / 详情页 / 海报）：仅加载当前用户所属部门、且授权对应绘图场景的知识库模板，以「标准模板 \+ 用户自定义需求」格式拼接，优先套用部门专属提示词模板

2. 对话场景：仅加载当前用户所属部门、且授权问答场景的参考资料，以「参考资料 \+ 用户问题」格式拼接，用于部门内部产品咨询、规则问答

3. 开关控制：关闭知识库时，直接使用用户原始输入，跳过拼接逻辑；所有资源严格遵循部门权限隔离，无越权访问

## 三、数据层设计

### 1\. 数据库说明

沿用现有 **SQLite \+ Prisma**，仅对原有 `KnowledgeBase` 数据表**新增字段**，不修改原有字段、索引、关联关系，历史数据完全兼容。

### 2\. 知识库数据表扩展设计

|字段名称|字段类型|原有 / 新增|字段说明|
|---|---|---|---|
|id|唯一标识|原有|主键 ID|
|name|字符串|原有|自动去除后缀的文档名称|
|originalName|字符串|原有|原始上传文件名|
|content|长文本|新增|解析、清洗后的文档正文（提示词 / 产品资料）|
|keywords|字符串数组|新增|检索关键词（自动提取 \+ 手动编辑）|
|scene|字符串数组|新增|绑定归属部门、部门授权业务场景列表，用于部门权限隔离与资源过滤|
|isEnabled|布尔值|原有|文档启用 / 禁用状态|
|isPriority|布尔值|原有|优先匹配标记|
|alias|字符串数组|原有|文档别名|
|createdAt/updatedAt|时间|原有|创建 / 更新时间|

### 3\. 部门与业务场景关联设计

新增部门体系，支持账号绑定部门、部门配置专属可使用业务场景，实现权限分层管控，场景枚举全局统一复用：

- `main-image`：电商 1:1 主图生成

- `detail-page`：电商 9:16 详情页分镜生成

- `poster`：海报设计生成

- `chat`：AI 对话问答

**部门权限规则**：每个部门可独立开通、关闭上述任意业务场景，仅已授权场景的知识库可被部门用户调用；超级管理员可查看、配置所有部门及场景权限。

### 4\. 文件存储规则

1. 上传文档：存储至原有 `storage/uploads` 目录，命名规则保留历史逻辑

2. 生成图片：存储至原有 `storage/results` 目录，完全无改动

## 四、前端功能设计（增量扩展）

### 1\. 知识库管理页面（原有页面扩展）

在现有知识库编辑弹窗 / 页面中，新增三项核心配置，适配部门权限体系，原有功能全部保留：

1. **关键词输入框**：支持手动增删、修改关键词，覆盖自动提取结果

2. **归属部门选择**：单选绑定知识库所属部门，实现资源部门隔离

3. **部门业务场景配置**：多选配置该知识库适配的部门授权场景，精准匹配使用场景

4. 保留原有：启用状态、优先匹配、别名编辑功能

### 2\. 生图工作台（权限自适应控件）

工作台自动适配当前登录账号的部门权限，无需手动选择部门，仅展示**当前部门已授权的业务场景**，新增知识库开关：

1. **自适应业务场景下拉框**：自动过滤、展示当前用户部门可使用的生成场景，无权限场景隐藏

2. **知识库启用开关**：全局控制是否加载本部门专属知识库模板，默认关闭（兼容旧流程）

### 3\. AI 对话界面（如有）

复用「知识库启用开关」，无额外复杂控件，开关状态联动检索服务。

### 4\. 部门权限控制（全新升级）

- **超级管理员**：拥有全部门、全知识库权限，可配置部门、绑定账号、开通部门业务场景、编辑所有知识库资源

- **部门管理员**：仅管理本部门知识库、本部门场景权限，可上传、编辑本部门知识库

- **普通运营用户**：仅可使用、查看**所属部门、已授权场景**的知识库资源，无编辑、删除、配置权限

## 五、应用服务核心流程

### 1\. 文档上传全流程

1. 前端上传文件 → 后端接收文件流

2. 保存文件至本地 `storage/uploads` 目录（原有逻辑）

3. 解析文档正文（区分 MD/TXT/PDF）

4. 自动清洗 Markdown 语法、空行、特殊符号

5. 算法自动提取文档核心关键词

6. 数据写入数据库（填充原有字段 \+ 新增 content/keywords/scene/归属部门字段）

7. 前端返回上传结果

### 2\. 生图请求全流程（区分开关状态）

#### 场景 A：知识库开关【关闭】（原有流程）

用户输入提示词 → 选择场景 → 点击生成 → 直接调用 iThinkAPI → 任务入队 \+ 图片保存输出（全流程无新增逻辑）

#### 场景 B：知识库开关【开启】（增强流程）

1. 用户选择业务场景、输入自定义提示词，发起生成请求

2. 调用通用检索服务：严格按「用户所属部门 \+ 部门授权业务场景 \+ 用户输入」三重条件精准匹配本部门知识库内容

3. 校验内容长度，截断超长文本，规避 API 限制

4. 按绘图模板规则拼接「标准模板 \+ 用户需求」，生成最终提示词

5. 调用 iThinkAPI 执行生成

6. 沿用原有任务队列、图片存储、预览下载逻辑

### 3\. 对话请求全流程（如有）

1. 用户输入问题，开启知识库开关

2. 仅检索当前用户所属部门、且授权chat场景的知识库内容

3. 按问答规则拼接「参考资料 \+ 问题」

4. 调用对话 API 返回结果

### 4\. 异常容错流程（全局兜底）

1. 文档解析失败：仅保留原始文件名，content 字段置空，不影响上传流程

2. 数据库检索异常：自动跳过知识库，使用用户原始提示词

3. 无匹配知识库：直接使用用户原始提示词，无报错

4. 文档内容超长：按固定字符数截断正文，保证 API 调用正常

## 六、非功能性设计

### 1\. 兼容性

1. 功能兼容：开关关闭时，系统行为与升级前完全一致，历史项目、历史任务不受影响

2. 格式兼容：支持主流提示词文档格式 `.md`/`.txt`/`.pdf`，自动适配格式清洗

3. 数据兼容：原有数据库表、文件存储目录、命名规则全部保留

### 2\. 性能

1. 检索性能：基于内存 \+ SQLite 查询，单条检索耗时极低，不影响生图响应速度

2. 内容限制：单文档、整体拼接提示词均做字符截断，防止 API 超长报错

3. 资源占用：无新增独立服务、无中间件依赖，保持原有系统轻量化特性

### 3\. 可扩展性

1. 场景扩展：新增短视频、文案生成等业务场景，仅需新增场景枚举值即可复用全套知识库能力

2. 格式扩展：后续新增 Word、Excel 等文档格式，仅扩展解析服务，不改动主流程

3. 权限规则扩展：可按需新增部门角色、细化场景权限粒度，权限体系独立解耦

### 4\. 安全性

1. API 密钥：沿用原有设计，密钥仅存服务端环境变量，不暴露至前端

2. 权限安全：沿用原有角色权限体系，管控知识库增删改操作

3. 文档安全：上传文件仅本地存储，无外部同步、外泄风险

## 七、部署与上线说明

1. 前置操作：执行数据库结构同步命令，仅新增字段，不清理历史数据

2. 部署方式：沿用原有 `npm run dev` 启动方式，无需额外部署组件

3. 灰度策略：默认关闭「知识库启用开关」，全员先使用原有功能，按需逐步开放新能力

4. 回滚方案：如需回滚，直接关闭前端知识库开关即可，无需回滚代码 / 数据库

## 八、方案总结

本方案以**增量扩展、无侵入**为核心思路，基于现有系统架构升级知识库能力，完美适配「上传 Markdown 绘图提示词模板，AI 自动调用模板结合用户需求生成内容」的核心诉求。

1. 架构简洁，完全复用现有技术栈与运维体系，上线成本、风险极低；

2. 部门隔离设计，实现多部门知识库资源、业务场景完全隔离，杜绝跨部门数据泄露与模板干扰；

3. 开关 \+ 容错机制双重保障，新旧业务平滑过渡；

4. 模块解耦，检索、解析服务全局通用，后续可快速扩展至更多 AI 生成场景。
