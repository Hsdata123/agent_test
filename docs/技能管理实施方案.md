# 知识库技能管理：用户上传方案

## 目标
让非开发同学在网页里"声明"一个技能（声明式，不写代码），自动出现在对话的 tools 里，模型可以调用。系统内置的 `searchKnowledgeBase` / `getAssetDetail` 保持 fallback 角色，UI 不展示。

## 1. 技能在 v1 里的形态
"参数化的 prompt 模板 + 白名单工具" 三件套：
- **何时调用**：name + description（暴露给 LLM 决定）
- **怎么调**：parameters（JSON Schema，告诉 LLM 怎么传参）
- **调了干啥**：executeMode + executeConfig（白名单动作，安全）
- **结果怎么用**：systemPrompt（拼在 content 前，提示 LLM 怎么用这条结果）

## 2. v1 支持的 executeMode（白名单，3 个）
| Mode | executeConfig 结构 | execute 行为 |
|---|---|---|
| `search_kb` | `{ queryParam: string, limitParam?: string, assetTypeParam?: string }` | 调 `searchKnowledgeBase.execute({[queryParam]: args.x, ...}, ctx)` |
| `get_detail` | `{ assetIdParam: string }` | 调 `getAssetDetail.execute({[assetIdParam]: args.x}, ctx)` |
| `no_op` | `{ template: string }` | `template` 支持 `{{args.key}}` 占位替换 |

不开放自定义 JS / eval，零脚本注入风险。

## 3. DB schema（新增 Skill 表）
```prisma
model Skill {
  id            String   @id @default(cuid())
  name          String   @unique
  displayName   String
  description   String
  parameters    String   // JSON Schema（字符串）
  executeMode   String   // search_kb | get_detail | no_op
  executeConfig String   // JSON
  systemPrompt  String?
  enabled       Boolean  @default(true)
  departmentId  String?
  createdById   String?
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
  deletedAt     DateTime?
}
```
- `name` 唯一（含软删）
- 软删：`deletedAt` 过滤；列表仍能查到被删条目以审计
- 全局技能 `departmentId = null`，只有 admin 能改

## 4. API（5 个路由）
- `GET    /api/skills`          列表（带 createdBy）
- `POST   /api/skills`          新建
- `GET    /api/skills/:id`      详情
- `PUT    /api/skills/:id`      修改
- `DELETE /api/skills/:id`      软删
- `POST   /api/skills/:id/test` 用 mock args 跑 execute

权限：admin 改全局/本部门，普通用户仅本部门。schema 校验用 AJV 或手写简单校验。

## 5. 前端（SettingsView 新 Tab）
「**技能管理**」：
- 表格：name / displayName / mode (Tag) / 启用 / 部门 / 创建人 / 操作
- 顶部"新建技能"按钮
- 模态分 4 段：
  1. **基础**：displayName / name（英文唯一，校验）/ description
  2. **参数 schema**：行编辑器（key / type 枚举 / description / required 勾选） + 实时 JSON 预览面板
  3. **执行配置**：跟随 executeMode 切换表单
     - search_kb：queryParam / limitParam / assetTypeParam
     - get_detail：assetIdParam
     - no_op：template 多行（带 `{{args.x}}` 占位说明）
  4. **systemPrompt**：多行文本
- 底部"测试"按钮 → 弹窗显示 `ok / 前 800 字 / matchedIds`
- 删除：确认弹窗（提示"软删，仍可在审计中恢复"）

## 6. 集成
- `lib/skills/registry.ts` 新增 `loadUserSkills()`：从 DB 查 `enabled=true, deletedAt=null` 的
- `listOpenAITools()` 合并 built-in（hidden）+ user；前端只看 user
- 5 秒 in-memory 缓存（`Map + Date.now`），避免每请求打 DB
- `getSkill(name)` 先查 user，再 fallback built-in；同名校验阻止冲突
- `lib/chat-runner.ts` 不动，registry 自动暴露 user skill 给 LLM
- 软删后 5 秒内从 LLM 可见集合消失（缓存刷新）

## 7. 风险
- 软删的 `name` 还占唯一索引 → 复用 name 时先校验 `deletedAt IS NOT NULL` 决定走 update-or-create；UI 给出"该 name 已被删除，是否恢复？"二选一
- 缓存与软删：删除时主动 `registry.invalidate()` 清掉
- `template` 替换只做 `{{args.x}}` 文本替换，**不 eval**

## 8. 验收清单
- AC-1 admin 新建 `search_kb` 类型技能 `competitor_analysis`，参数 `{query:string}`
- AC-2 对话中模型调到这个技能，过程日志「🛠 调用技能：competitor_analysis(query="...")」出现
- AC-3 软删该技能，5 秒内对话不再看到；列表仍能查到带"已删除"标
- AC-4 普通用户只看本部门技能，admin 看得到所有
- AC-5 测试按钮：用 `{query: "防晒伞"}` 跑出真实命中 + 预览 800 字
- AC-6 内置 `searchKnowledgeBase` / `getAssetDetail` UI 不可见但对话 LLM 仍能调用
