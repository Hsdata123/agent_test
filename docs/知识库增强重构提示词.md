# 知识库增强重构操作提示词（可直接复用）

基于现有 Next.js 15 + Prisma + SQLite + Ant Design 单体项目「AI 电商主图 / 详情页生成管理系统」，对**知识库模块**做无侵入式重构：把单一资源池升级为「部门权限隔离 + 业务场景动态配置 + 智能检索 + 提示词增强」体系。以下提示词描述了完整的实施细节，复制后可在任何一份同结构代码上 1:1 还原。

===========================
一、目标与原则
===========================
- 现有登录、项目管理、生图队列、产品白底图匹配、API 配置、对话等流程**完全保留**，新功能通过「每次任务独立开关」灰度启用（默认关闭）
- 角色枚举**不新增**：复用 `admin/creator/editor/viewer`，语义重映射为超管 / 部门管理员 / 部门编辑 / 部门只读
- 场景**不预设枚举**，由超级管理员 / 部门管理员动态配置
- 走 `prisma/init.mjs` 的 `CREATE TABLE IF NOT EXISTS` + `ensureColumn` 增量迁移，**不跑 `prisma db push`**，避免 SQLite 删表重建
- 现有数据零迁移面：复用 `extractedText` 当 `content`、`tags` 当 `keywords`，仅新增 2 张表 + 4 个字段

===========================
二、字段策略
===========================
- 新表：`Department`、`BusinessScene`
- 新字段：
  - `User.departmentId String?`（单选）
  - `KnowledgeAsset.departmentId String?`
  - `KnowledgeAsset.scenes String @default("[]")`（JSON 数组）
  - `GenerationTask.knowledgeEnhanced Boolean @default(false)`
- 默认部门 `id="dept_default" code="default" name="默认部门"`，seed 时由 `init.mjs` 幂等 INSERT，`seed.ts` upsert
- 三条 backfill：
  - `UPDATE User SET departmentId='dept_default' WHERE departmentId IS NULL`
  - `UPDATE KnowledgeAsset SET departmentId='dept_default' WHERE departmentId IS NULL`
  - `UPDATE KnowledgeAsset SET scenes='[]' WHERE scenes IS NULL OR scenes=''`

===========================
三、文件改动清单（按层）
===========================

1. **数据层**
   - `prisma/schema.prisma`：新增 2 个 model + 4 个字段

2. **后端服务层（纯逻辑，无 HTTP）**
   - `lib/dept-scope.ts`（新）：`DEFAULT_DEPARTMENT_ID`、`isAdmin`、`getEffectiveDepartmentId`、`canEditAsset`、`canManageScene`（async + `roleHasPermission`）、`requireDeptAccess`、`scopedKnowledgeWhere`
   - `lib/departments.ts`（新）：CRUD；最后部门禁止删；存在绑定 user/asset 时拒绝删；`ensureDefaultDepartment()` 幂等
   - `lib/scenes.ts`（新）：`parseScenesString`（try/catch 容错）、`serializeScenes`（去重 trim）、CRUD、`getAllowedScenesForUser`（admin 看全部）
   - `lib/knowledge-retrieval.ts`（新）：`retrieveKnowledge({ userDepartmentId, isAdmin, allowedScenes, query, options })`，候选 200 + JS 打分（精确名+100、别名+80/30、token 20、产品名 18、tags 12、场景交集+10、正文+5/token+1、`preferred`+50），异常吞掉返回 `[]`，正文 8000 字截断
   - `lib/prompt-enhancement.ts`（新）：`enhanceImagePrompt` 追加块（不替换原 prompt）、`enhanceChatContext` 拼接 context
   - `lib/auth.ts`：补 `requireDeptAdmin(targetDepartmentId?)`
   - `lib/roles.ts`：补 `getAllowedScenesForUser`

3. **API 层**
   - 新建：
     - `app/api/settings/departments/route.ts`（GET 任意、POST admin）
     - `app/api/settings/departments/[id]/route.ts`（GET/PATCH/DELETE admin）
     - `app/api/settings/scenes/route.ts`（GET admin 全 / 其他仅本部门、POST admin 任意 / creator 本部门）
     - `app/api/settings/scenes/[id]/route.ts`（GET/PATCH/DELETE + `canManageScene`）
   - 改造（保持向后兼容，新字段全部可选）：
     - `app/api/knowledge/assets/route.ts` GET 加 `scopedKnowledgeWhere`，admin 可传 `?departmentId=` 过滤
     - `app/api/knowledge/assets/[id]/route.ts` GET 校验作用域、PATCH 接收 `departmentId`+`scenes`、admin 限跨部门迁移
     - `app/api/knowledge/upload/route.ts` POST 接收 `departmentId`（admin 可指定）+ `scenes`（JSON 数组或逗号分隔字符串）
     - `app/api/knowledge/text/route.ts` POST 同样接收 `departmentId`+`scenes`
     - `app/api/generation/batch/route.ts` 透传 `knowledgeEnhanced`
     - `lib/create-batch.ts` 从 `generationConfig.knowledgeEnhanced` 写入 `GenerationTask`，并给 `templateAsset`/`portraitAsset` `findFirst` 加 `deptScope`
     - `lib/generation.ts` `runTask` 加载 `taskUser`、若 `task.knowledgeEnhanced===true` 调 `loadKnowledgeEnhancement`、在 `resolveMainPrompt`/`resolveDetailPrompt` 之后用 `enhanceImagePrompt` 注入；非 admin 时 `templateAsset`/`portraitAsset` 自动加 `departmentId` 过滤
     - `app/api/chat/route.ts` 接收 `useKnowledge:boolean`，true 时走 `retrieveKnowledge`+`enhanceChatContext`，默认保留原 useAll/selectedKnowledge 旧路径

四、关键 SQL 模板（init.mjs 末尾追加）
===========================
```sql
CREATE TABLE IF NOT EXISTS Department (
  id TEXT PRIMARY KEY NOT NULL,
  name TEXT NOT NULL UNIQUE,
  code TEXT UNIQUE,
  description TEXT,
  status TEXT NOT NULL DEFAULT 'active',
  createdAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updatedAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE IF NOT EXISTS BusinessScene (
  id TEXT PRIMARY KEY NOT NULL,
  departmentId TEXT NOT NULL,
  sceneKey TEXT NOT NULL,
  sceneName TEXT NOT NULL,
  description TEXT,
  createdAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updatedAt DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE(departmentId, sceneKey),
  FOREIGN KEY (departmentId) REFERENCES Department(id) ON DELETE CASCADE
);
-- ensureColumn 调用（顺序无关）：GenerationTask.knowledgeEnhanced BOOLEAN DEFAULT 0
-- User.departmentId TEXT; KnowledgeAsset.departmentId TEXT; KnowledgeAsset.scenes TEXT DEFAULT '[]'
INSERT OR IGNORE INTO Department (id, name, code, description, status, createdAt, updatedAt)
VALUES ('dept_default', '默认部门', 'default', '系统初始部门，可重命名或新增其他部门', 'active', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP);
UPDATE User SET departmentId='dept_default' WHERE departmentId IS NULL;
UPDATE KnowledgeAsset SET departmentId='dept_default' WHERE departmentId IS NULL;
UPDATE KnowledgeAsset SET scenes='[]' WHERE scenes IS NULL OR scenes='';
```

===========================
五、风险与缓解
===========================
- `lib/generation.ts` 改造影响 KB-off 路径：用 `if (task.knowledgeEnhanced)` 守卫；KB-off 时 `result.prompt` 应与重构前**字节一致**
- `Dashboard.tsx` 已 2.7k 行，再加 600 行集中改在 `KnowledgeView` / `SettingsView` / 末尾 `DepartmentAdminView`，新组件不破坏现有 body
- 走 `node prisma/init.mjs && npx prisma generate`（即 `npm run db:push`），**绝不直接跑 `prisma db push`** 删表
- SQLite 中文 LIKE 性能/精度问题：检索拉宽候选 200 条 + JS 打分排序，不依赖 LIKE 排序
- `templateAsset`/`portraitAsset` 跨部门泄漏：Phase 3 在 `lib/create-batch.ts` 与 `lib/generation.ts` 同步加 dept 作用域

===========================
六、端到端验证清单
===========================
1. AC-1 `npx tsc --noEmit` 0 错
2. AC-2 `node prisma/init.mjs` 成功；`Department` 表 ≥1 行；4 个新字段全部存在
3. AC-3 `npx tsx prisma/seed.ts` 后 admin/operator 的 `departmentId` = `dept_default`
4. AC-4 KB 关**闭**生图，`result.prompt` 与重构前**字节一致**（人工 diff）
5. AC-5 KB 开**启**生图，`result.prompt` 末尾出现「以下是从知识库检索到的参考资料」块并含资产名
6. AC-6 admin 创建新部门「美妆一组」+ 场景 `mask`，DB 可查
7. AC-7 operator (creator) 登录 `GET /api/settings/scenes` 只返回本部门；POST 跨部门场景返回 403
8. AC-8 A、B 部门各 1 个 viewer + 1 个资产，A 部门 viewer 看不到 B 部门资产
9. AC-9 ChatProjectsView 开「使用知识库」发送，请求体含 `useKnowledge:true`；响应内容参考本部门资料
10. AC-10 KB 开启但**无任何资产命中**时，生图/对话正常完成，prompt = 原始 prompt（无 KB 块）
11. AC-11 注入临时 throw 让 `retrieveKnowledge` 抛错，生图/对话降级到原始 prompt 完成，无用户可见错误

七、可复用模式（避免重复造轮子）
===========================
- 文档解析：`extractDocumentText(file, originalName)`（`lib/document-extract.ts:14`）已支持 MD/TXT/PDF/DOCX/XLSX/PPTX，**无需改动**
- JSON 容错 try/catch：`lib/roles.ts:139` 的 `jsonPermissions` 模式
- 幂等建表：`lib/roles.ts:48` 的 `ensureRoleTable` 模式 → `ensureDefaultDepartment`
- `ensureColumn(table, column, def)`：`prisma/init.mjs:208`
- 提示词增强块**追加在 `appendReferenceRolePrompt` 之后**，不替换
- 鉴权工具：`requireUser` / `requireAdmin` / `canEdit` / `roleHasPermission` / 新增 `requireDeptAdmin`
- AntD `Tabs items` 数组模式（`components/Dashboard.tsx` 已有结构）→ 直接插入新 tab
