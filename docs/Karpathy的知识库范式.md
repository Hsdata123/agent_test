## Karpathy的知识库范式

#### 背景

​	传统的RAG→临时检索，即每次查询都是临时的，对于大模型而言每次查询知识库都是一个全新的知识库，总结完成之后，用完就扔了。下一次查询又是重复劳动，没有积累。

#### 新范式

1. 持久wiki

   - 让LLM增量构建和维护知识
   - 结构化互相链接的Markdown集合
   - 阅读、提取、整合新的知识
   - 更新实体、标记矛盾、持久更新
   - 实现知识增长复利

2. 管理架构

   - 原始数据层：不可变的所有用户上传的文件、图片等等，llm只读
   - 知识库层：LLM生成的Markdown文件集合、概念、摘要、对比分析，LLM拥有所有权限，用户只读。
   - 规则层：知识库的宪法与配置，定义WIKI结构和LLM处理规则，告诉LLM如何处理新知识以及维护旧知识

3. 工作流

   1. 用户上传一批知识库文件——需要提醒用户每一个批次的文件都是同一个场景下的，不能毫无关联（这里为了解决上下文问题，看是每个文件异步到AI，然后收集汇总结果再到AI模型总结，形成改批次文件的初步探索，即保存成WIKI）
   2. 上传且初步探索完毕之后，AI会根据探索结果询问用户这些文件的问题是什么？交由用户提问。
   3. AI回答用户的提问的结果，可以由用户选择是否归档（存回WIKI）
   4. 最后每周或者每多少次提问或者每多少次上传知识库之后，开启健康检查。找出矛盾数据、知识、没有链接的孤岛wiki。甚至后续可以在体检之后增加AI的知识库建议。
